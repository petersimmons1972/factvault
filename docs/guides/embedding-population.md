# Embedding Population: `worker embed`

The `worker embed` subcommand backfills the `vector(1024)` embedding columns that are left NULL by
the extract and collect workers. Embeddings are generated by the BAAI/bge-m3 embedder sidecar and
stored in Postgres via pgvector. Once entities have embeddings, cosine-similarity story seeding
becomes available in the retrieval layer.

---

## Why Embeddings Matter

factvault's retrieval service (`internal/retrieval/service.go`) uses a two-path strategy for
seeding story queries:

1. **Cosine path** (preferred): embed the query text, call `vectorStore.SearchNearest`, return
   entities whose cosine similarity exceeds 0.6.
2. **ILIKE fallback**: substring match on `entities.label` and `description`. Always available,
   lower semantic precision.

The cosine path is silently skipped when embeddings are NULL. Running `worker embed` after
extraction populates the embedding columns and activates the cosine path for all subsequently
seeded stories. A downed embedder never causes a 500 -- the ILIKE fallback fires automatically.

---

## What Gets Embedded

The worker runs one backfill pass over three tables for the given tenant:

| Table | Text used for embedding |
|-------|------------------------|
| `entities` | `label` + `description` (space-separated; description omitted if empty) |
| `sources` | `title` + first 2048 chars of `raw_text` |
| `statements` | `"subject property value"` rendered from `val_text`, subject label, and property slug |

Rows where `embedding IS NULL` are processed. Rows that already have an embedding are skipped.
Each table is processed in a separate transaction so a failure in one table does not roll back
progress in others.

---

## Usage

```bash
./bin/factvault worker embed \
  --tenant "$FACTVAULT_DEV_TENANT_ID" \
  --dsn "$FACTVAULT_DATABASE_URL"
```

The embedder URL defaults to `http://localhost:8080` (or `FACTVAULT_EMBEDDER_URL`). Override
explicitly when running outside the default port:

```bash
./bin/factvault worker embed \
  --tenant "$FACTVAULT_DEV_TENANT_ID" \
  --embedder-url http://localhost:8081
```

Output:

```
embed: populated=47 skipped=0
```

The command is fully idempotent: run it multiple times and rows with existing embeddings are
counted as `skipped`, not re-embedded.

---

## Flags

| Flag | Default | Env var | Description |
|------|---------|---------|-------------|
| `--embedder-url` | `http://localhost:8080` | `FACTVAULT_EMBEDDER_URL` | Embedder service base URL |
| `--tenant` | required | -- | Tenant UUID |
| `--dsn` | -- | `FACTVAULT_DATABASE_URL` | Postgres DSN |
| `--limit` | `100` | -- | Max rows per table per run (inherited from `worker` persistent flags) |

---

## The Embedder Sidecar

The embedder is a Python HTTP service that wraps BAAI/bge-m3 (1024-dimensional vectors). It is
started by `docker compose up -d embedder` and exposes:

- `POST /embed` -- accepts `{"texts": [...]}`, returns `{"vectors": [[...], ...]}`
- `GET /healthz` -- returns 200 when the model is loaded; 503 while loading

**First boot warning:** BAAI/bge-m3 is approximately 2 GB. On first startup the container
downloads the model before it can serve requests. The `/healthz` endpoint returns 503 during this
period. Expect a wait of several minutes on a fresh deployment. `factvault doctor` will show the
embedder as `WARN` or `FAIL` until the model finishes loading.

The `embed.Client` (`internal/embed/client.go`) calls `POST /embed` and converts the returned
`[][]float64` to `[][]float32` for pgvector storage. If the embedder returns a non-200 status,
`worker embed` exits with an error and no rows are written.

## Operational Placement

Run `worker embed` after `worker extract` has produced facts and after the embedder is confirmed
healthy. The recommended order:

```bash
# 1. Source ingestion
./bin/factvault worker collect  --tenant "$FACTVAULT_DEV_TENANT_ID"  # or: worker rss / worker research
./bin/factvault worker archive  --tenant "$FACTVAULT_DEV_TENANT_ID"
./bin/factvault worker extract  --tenant "$FACTVAULT_DEV_TENANT_ID" \
  --llm-model llama3.1:8b --llm-base-url http://localhost:11434/v1

# 2. Fact enrichment
./bin/factvault worker corroborate --tenant "$FACTVAULT_DEV_TENANT_ID"

# 3. Embedding population (activates cosine seeding)
./bin/factvault worker embed    --tenant "$FACTVAULT_DEV_TENANT_ID"

# 4. Dossier precompute
./bin/factvault worker dossier  --tenant "$FACTVAULT_DEV_TENANT_ID"
```

In a production loop, run `worker embed` on a schedule after extract and before dossier.
Incremental runs are cheap: the `--limit` cap means each invocation processes at most N rows per
table, so the worker can run frequently without hammering the embedder.

## Checking Embedder Readiness

```bash
# Via doctor (shows embedder check line)
./bin/factvault doctor --dsn "$FACTVAULT_DATABASE_URL" --required-only

# Direct health check
curl -s http://localhost:8081/healthz
# 200 = ready; 503 = model still loading
```
